# Database schema management with Ocsigen Start and PG'OCaml

A recommended approach, not a requirement of Ocsigen Start: it keeps one replayable file
for the application schema, which suits the build-time checking of `[%pgsql]` queries.

## Contents

- Two schema files
- Guards that make update.sql replayable
- Makefile targets
- Build order

## Two schema files

- `myapp.sql`: the Ocsigen Start bootstrap (schema `ocsigen_start`, tables `users`,
  `groups`, `emails`, ...). Generated by the template and never edited, so that Ocsigen
  Start's own upgrade scripts keep applying.
- `update.sql`: everything the application adds. Idempotent and re-runnable: applied to a
  fresh database it creates the application schema, applied to an existing one it brings it
  up to date, applied twice it changes nothing.

## Guards that make update.sql replayable

```sql
\set ON_ERROR_STOP true
SET client_min_messages TO WARNING;

CREATE SCHEMA IF NOT EXISTS myapp;

CREATE TABLE IF NOT EXISTS myapp.items (
  id         bigserial PRIMARY KEY,
  owner      bigint NOT NULL REFERENCES ocsigen_start.users (userid),
  created_at timestamptz NOT NULL DEFAULT now(),
  title      text NOT NULL
);

ALTER TABLE myapp.items ADD COLUMN IF NOT EXISTS notes text;

CREATE INDEX IF NOT EXISTS items_owner ON myapp.items (owner);
```

Append later columns as `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`; never rewrite an earlier
statement, since existing databases have already run it. Guard data migrations that are not
naturally idempotent with `WHERE NOT EXISTS` or a small version table.

## Makefile targets

The template's `Makefile.db` provides `db-init` (local PostgreSQL cluster), `db-create`,
`db-schema` (applies `myapp.sql`), `db-upgrade` (Ocsigen Start upgrade file),
`db-snapshot`, `db-psql` and `db-drop`. Add a target for the application file, and apply it
from `db-schema` too so that a fresh database gets both:

```make
UPDATE_FILE ?= update.sql

db-update:
	psql -d $(DB_NAME) -f $(UPDATE_FILE)
```

Fresh database: `make db-create db-schema db-update`. Existing database: `make db-update`.
Check the project's `Makefile.db` first: some projects already chain `update.sql` into
`db-schema`.

## Build order

`[%pgsql]` queries are type-checked against the live database. Run `make db-update` before
`make`, and in production apply `update.sql` before deploying the new binary. A build error
about an unknown column or relation usually means the migration has not been applied to the
database the build is using.
